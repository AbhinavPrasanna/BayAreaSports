# Season records

## Valkyries–Dream Finals series

The 2026 WNBA Finals has its own series record, separate from the season/playoff totals. Each of the seven reviewed matchups shows its Finals game number; Games 6 and 7 are labeled “If necessary.” Team rows show Finals totals after completed games and entering upcoming games. Game details contain a separate Finals panel, and My teams adds the current Finals win/loss tally. Historical totals use only results through that game, while future games use only results already completed as of the current time. Spoiler protection hides all Finals tallies, including the sidebar; revealing one game leaves sidebar totals hidden.

`src/shared/finals.ts` scopes the series to reviewed BALLDONTLIE game IDs, season and both team identities. Official IDs/game numbers/conditional flags were matched against the [WNBA schedule JSON](https://cdn.wnba.com/static/json/staticData/scheduleLeagueV2.json) on October 22, 2026. Regular-season meetings and earlier playoff games are excluded. New seasons/series need their own reviewed mapping; an opponent alone never identifies a Finals series.

Series wins/losses are calculated from the existing complete playoff record snapshot with the latest schedule corrections overlaid. Missing earlier history or invalid final totals remain pending. Scheduled/live games do not count as wins/losses, and corrections recalculate the tally. This adds no provider requests or migration. The read-only game API attaches `records.finals` to matching game responses, and `teamRecords[].finals` provides current followed-team totals. Existing 15-second refresh and reconnect handling keep these derived values current.

The My teams sidebar shows the followed team's current regular-season record, with a separate playoff record after playoff games are played. Both teams on game cards show their record **entering that game**. Final-game details also show **after this game** totals. NBA/WNBA use wins–losses; NFL uses wins–losses–ties. Season labels identify NBA's two-year season and NFL/WNBA's season year. Spoiler protection hides current, entering and postgame records as well as scores; revealing one game's score does not reveal sidebar records for the rest of the season.

Records are calculated from full-season, phase-filtered BALLDONTLIE games. No standings subscription or additional key is required. The league adapters use verified filters: NBA `season_type=regular|playoffs`, NFL `season_types[]=2|3`, WNBA `season_type=2|3`. NFL's year stays with the previous season through February, NBA's through June, and WNBA uses the calendar year. Regular-season/playoff results are never combined. Scheduled, live, postponed and canceled games do not change a record. Missing final scores and tied basketball finals leave the affected total unavailable instead of fabricating a number.

Migration **006** adds game season/phase metadata and separate record snapshot tables. The single worker loads at most one season page per minute using the **same persistent 14-second sports-provider throttle** as score ingestion. Each league/phase snapshot is refreshed hourly. NBA/WNBA requests include the full season through the following Pacific date; NFL loads its season schedule. The following date covers late UTC games. Up to 40 pages are allowed per snapshot. Paginated rows are staged under a generation; readers see them only when the final page succeeds. Restarts resume the cursor. Errors back off, preserving the previous complete generation. Initial records say loading/pending until coverage is complete.

The regular score worker's newer observations overlay matching snapshot games, so followed-team records respond to final scores and corrections with the normal score checks. Older games and opponents' other games update with the hourly season snapshot. Checked timestamps and delayed labels distinguish stale snapshots; snapshots older than six hours or with an error are marked delayed. Records are recomputed from game results rather than incremented counters, preventing double counting and allowing corrections to propagate to later games. For historical cards, only results before that game's start count; upcoming cards use the currently completed results rather than predicting future outcomes.

`/api/games` responses add `teamRecords` independently of the selected view/filter, and optional `records` on each game; game details carry the same before/after records. Browser refresh/reconnect handling stays with the existing 15-second mechanism. All provider calls remain worker-side. Full-league record rows are isolated from the schedule's `games` table, so opponents do not become followed teams or create extra schedule cards.

Operational checks: bounded worker events `season_records_page`, `season_records_failed` and `season_records_storage_failed`; table `record_sync` holds coverage, cursor, last success and error. Record failures do not fail the score service's readiness check. Backups contain `record_sync`, `record_games` and the request gate. A restore must include six migrations and published record generations. Previous application images tolerate the additive schema; roll back images without reversing migration 006.
